## DELETE `/reports/emails`

**DELETE Report Emails**

Delete campaign email records by their IDs. This permanently removes the email log entries from the database.

**Auth:** ApplicationPasswords

**Request body** (`application/json`, required)

- `email_ids` (array<integer>) **required** — Array of campaign email IDs to delete.

Example:

```json
{
  "email_ids": [
    101,
    102,
    103
  ]
}
```


**Responses**

- **200** — Emails deleted successfully.

  Schema (`application/json`):

  - `message` (string)

  Example:

```json
{
  "message": "Selected emails have been deleted"
}
```

## GET `/reports/ajax-options`

**GET Ajax Options**

Retrieve searchable, paginated option items for various entity types. Used by select dropdowns that need server-side search. Supported `option_key` values include: `woo_categories`, `woo_products`, `product_selector_woo`, `product_selector_woo_order`, `edd_products`, `product_selector_edd`, `voxel_products`, `product_selector_voxel`, `voxel_product_types`, `campaigns`, `funnels`, `email_sequences`, `companies`, `post_type`, `company_industries`, `company_types`, `users`. Unrecognized keys are passed to the `fluentcrm_ajax_options_{key}` filter.

**Auth:** ApplicationPasswords

**Query parameters**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `option_key` | string | yes | The type of options to retrieve. |
| `search` | string | no | Search term to filter results. |
| `values` | array<integer> | no | Array of IDs that must be included in the results regardless of search term. |
| `sub_option_key` | string | no | Sub-type filter. Used with `woo_products` (for product type) and `post_type` (for the WordPress post type slug). |


**Responses**

- **200** — Options retrieved successfully.

  Schema (`application/json`):

  - `options` (array<object>)
    - `id` (any) — Option identifier.
    - `title` (string) — Display label.

  Example:

```json
{
  "options": [
    {
      "id": 5,
      "title": "Summer Campaign - 5"
    },
    {
      "id": 3,
      "title": "Welcome Series - 3"
    }
  ]
}
```

## GET `/reports/email-performance`

**GET Email Performance**

Retrieve aggregated email performance metrics including totals and percentages for sent, delivered, opened, clicked, and bounced emails. The `days` parameter controls the time window: a positive integer means the last N days, `0` means all time, and omitting it defaults to the last 30 days.

**Auth:** ApplicationPasswords

**Query parameters**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `days` | integer | no | Number of days to look back. Use `0` for all time. Defaults to 30 days if omitted. |


**Responses**

- **200** — Email performance metrics retrieved successfully.

  Schema (`application/json`):

  - `stats` (object)
    - `totals` (object) — Absolute counts for each metric.
      - `sent` (integer) — Total emails sent.
      - `delivered` (integer) — Delivered emails (sent minus bounced).
      - `opened` (integer) — Emails opened at least once.
      - `clicked` (integer) — Emails with at least one link click.
      - `bounced` (integer) — Bounced emails.
    - `percentages` (object) — Percentage rates. Delivery and bounce rates are based on (sent + bounced). Open and click rates are based on delivered.
      - `delivered` (number) — Delivery rate percentage.
      - `opened` (number) — Open rate percentage.
      - `clicked` (number) — Click rate percentage.
      - `bounced` (number) — Bounce rate percentage.

  Example:

```json
{
  "stats": {
    "totals": {
      "sent": 10000,
      "delivered": 9800,
      "opened": 4500,
      "clicked": 1200,
      "bounced": 200
    },
    "percentages": {
      "delivered": 96.08,
      "opened": 45.92,
      "clicked": 12.24,
      "bounced": 1.96
    }
  }
}
```

## GET `/reports/options`

**GET Report Options**

Retrieve option sets by specifying a comma-separated list of field names. Each field name maps to an internal method that returns the corresponding data (e.g., `countries`, `lists`, `tags`, `campaigns`, `statuses`, `editable_statuses`, `contact_types`, `email_sequences`, `automation_funnels`, `companies`, `segments`, `roles`, `user_roles_options`, `profile_sections`, `custom_fields`, `sms_statuses`). Only recognized field names are processed; unknown names are silently skipped.

**Auth:** ApplicationPasswords

**Query parameters**

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `fields` | string | yes | Comma-separated list of option fields to retrieve (e.g., `lists,tags,statuses`). |
| `with_count` | array<string> | no | Array of field names for which to include subscriber counts. Currently supports `lists`. |


**Responses**

- **200** — Options retrieved successfully. The response contains an `options` object whose keys depend on the requested fields.

  Schema (`application/json`):

  - `options` (object) — Object containing the requested option sets. Keys match the requested field names.
    - `lists` (array<object>)
      - `id` (integer)
      - `slug` (string)
      - `title` (string)
      - `subscribersCount` (integer) — Only present when `with_count` includes `lists`.
    - `tags` (array<object>)
      - `id` (integer)
      - `slug` (string)
      - `title` (string)
      - `value` (string)
      - `label` (string)
    - `statuses` (array<object>)
      - _(object)_
    - `campaigns` (array<object>)
      - `id` (integer)
      - `title` (string)
    - `countries` (array<object>)
      - `code` (string)
      - `id` (string)
      - `slug` (string)
      - `title` (string)

  Example:

```json
{
  "options": {
    "lists": [
      {
        "id": 1,
        "slug": "newsletter",
        "title": "Newsletter"
      }

    "tags": [

        "id": 1,

        "label": "VIP"
      }
    ],
    "statuses": [
      {
        "id": "subscribed",
        "title": "Subscribed"
      }
    ]
  }
}
```
